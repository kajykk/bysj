## 一、结论（先行）

**T3 判定门槛未通过 ⇒ 立项阴性结论。**

| 门槛条件 | 结果 |
|---|---|
| `ERDE50(c) ≤ ERDE50(a)` | ❌ 0.1958 > 0.0052 |
| `F_latency(c) ≥ F_latency(a)` | ❌ 0.5820 < 0.6721 |

方向 C **不进 T4（预警链路接入设计）**，不改进主路径。按本轮边界：
「若 T3 为阴性，如实立项阴性结论，不自我说服加码」。

## 二、三档基线读数（synthetic，5-fold 按用户分组）

`StratifiedGroupKFold(n_splits=5, groups=user_id)`，seed=20261019，k=50；
阈值只在 train 折选（`θ*` 五折全部收敛到 0.40）。

| 档 | ERDE50 ↓ | F_latency ↑ | n_case | n_control |
|---|---|---|---|---|
| (a) 时点 + 固定阈值 | **0.0052** | 0.6721 | 200 | 200 |
| (b) 分层阈值 | **−0.0455** | **0.7049** | 200 | 200 |
| (c) 学习式停止（MLP） | 0.1958 | 0.5820 | 200 | 200 |

**档 (b) 是本轮唯一优于 (a) 的**：ERDE −0.0455（负值 = 平均提前于 onset 报警）、
F_latency +0.0328。但 (b) 与 (c) 都不是本轮判定对象（门槛只比 c vs a），
(b) 的优势仅作参考记录。

## 三、阴性归因（诊断读数，synthetic）

| 量 | (a) | (c) | 解读 |
|---|---|---|---|
| 中位延迟 | +1 篇 | **+0 篇** | c 更接近 onset |
| 平均延迟 | +0.55 篇 | **−1.41 篇** | c 平均**提前**报警（学习式停止的初衷实现了） |
| 提前报警数 | 52/190 | 87/176 | c 更激进取早 |
| **未报警（漏 case）** | **10** | **24** | **c 漏报翻倍** |
| 对照误报 | 161/200 | 190/200 | c 的 FP +18% |

∴ c 的 ERDE 被漏报主导（24 个 penalty=1.0），F_latency 被 FP 主导
（T1 §2.3：FP 权重全额 1.0，c 的 P 从 0.596 掉到 0.553）。

**归因结论**：这套配置下 MLP 停止策略「过激」——提前量换来的是漏报与误报同步上升。
可解释，但**不构成对「学习式停止」范式的否定**：本轮只用 5 维标量累积特征
（cum_mean_p / p_last / p_max / p_min / n_obs）+ 单阈值 0.5 决策，未调正则、未做
每用户 top‑m 停止、未在 ERDE 上做结构化寻优。按纪律，**不做参数自救**
（改参数直到达标 = 在评估集上调参，正是 B 轮 L3 教训）。

## 四、基准局限（诚实记账，影响结论的外推）

**该仿真基准任务过易**：a 档 ERDE50=0.0052、平均延迟仅 0.55 篇。
根因是构造方式：case 用户 onset 后段全部由 PHQ-9≥10 的文本组成，
而文本内容与分数强对应 ⇒ 时点模型近乎完美。后果：

1. 三档拉不开统计差距，门槛判定对实现细节敏感；
2. **不能据此推断任何真实世界结论**（仿真器缓解的是"无数据可用"，
   不缓解"分布过于干净"）；
3. 未来若做真实纵向数据，需重建基准或加噪（如 onset 前后混入同分段文本、
   引入时点缺失）。这列为**未验证/下一步**，本轮不动基准（改基准直到结论变化
   即 cherry-pick）。

## 六、开发期修正记账（两处，均已修复并有回归测试）

1. **ERDE「未报警」语义 bug**：首版把未报警编码为 `d=n+1`，使 `d ≤ o+k` 检查
   失效而得到**小负 penalty**（应为恒 1.0）。手算自检当场抓住
   （`ERDE 未报警 ⇒ 1.0` got −0.6）。改为 `None` 编码。
   —— eRisk 原义：never decides ⇒ penalty 恒 1，**不是「在序列末报警」**。
2. **F_latency 自检期望值写错**：手算 P=1.5/(1.5+1)=0.6 误写成 0.4，
   正确 F=0.75。自检先红后绿，证明自检有效。
3. **HashingVectorizer L2 归一断言错**：`m.sum()` 实际为 `sqrt(nnz)` 而非 1，
   改为断言平方和 =1。
