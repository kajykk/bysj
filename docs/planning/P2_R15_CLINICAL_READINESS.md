## 一、结论摘要

**一句话结论**：DWS 在"工程完成度"上已明显高于同类毕业设计作品，但按 NMPA 医疗器械（SaMD）路径衡量，当前状态**不是"临门一脚"，而是尚未进入注册准备阶段**——存在 3 类根因性阻断项，且其中 2 类无法靠写代码解决。

三类阻断项（详见 §六）：

| 类别 | 阻断项 | 性质 | 能否靠迭代代码解决 |
|---|---|---|---|
| **主体资格** | 注册申请人须为境内**企业法人**（个人/高校不能作为注册人）`[待核验]` | 组织与法律 | 否——必须成立/挂靠企业实体 |
| **产品定性** | 未决：是"健康管理软件"还是"辅助决策医疗器械" | 策略与声明 | 部分——可通过削减功能声明规避，但会牺牲核心价值 |
| **证据链** | 无金标准、无独立/第三方测试集、无外部验证、无风险管理与软件生命周期文档 | 方法学与文档 | 是——但工作量为数月量级 |

**三条可选路径的取舍建议**：

| 路径 | 产品声明 | 监管后果（本报告判断） | 建议 |
|---|---|---|---|
| **甲档** 量表呈现 + 心理健康教育 + 转介导航 | 不做风险判定、不输出概率/等级 | 可能**不作为医疗器械管理**（健康管理/健康教育软件）`[待核验]` | 合规成本最低，可作为"先落地、后升级"的起步形态 |
| **乙档** 筛查预警工具（输出风险等级供咨询师参考） | "辅助识别需重点关注的学生" | 极可能按医疗器械管理；管理类别取决于是否提供**决策支持** `[待核验]` | 与项目现有能力最匹配，但需补齐 §五 全部证据链 |
| **丙档** 辅助诊断/辅助决策（给出诊断倾向或干预建议） | "辅助诊断" | 一般按**三类**管理，且通常须**临床试验** `[待核验]` | 本阶段不可行（受限于主体资格与金标准缺失） |

> **核心洞察**：项目当前 `01-model-card.md` §2.2 已把"临床诊断或医疗决策"列为**禁用场景**，这与乙/丙档所需的"明确预期用途与临床获益陈述"**方向相反**。若要走注册，必须一次性重构产品声明；若维持现有免责声明，则只能走甲档或"非医疗器械"路线。**这是本报告要求决策者首先拍板的问题，先于任何技术补齐。**

## 三、项目现状盘点（四层）

### 3.1 模型层

| 槽位 | 现役产物 | 指标（口径见括号） | 证据路径 |
|---|---|---|---|
| 结构化 | LogisticRegression（Mendeley PHQ-9 真实数据） | F1=0.8955 / AUC=0.9174 / Acc=0.8811 | `backend/models/MODEL_REGISTRY.md` §1 |
| 文本 | 双语 TF-IDF + LR | groupwise F1=**0.5864** / AUC=0.8437 / Brier=0.128（n=8379，threshold=0.5 行） | `docs/planning/backend_text_bilingual_v2_metrics.json` |
| 生理 | MLP（input_dim=13） | F1=0.857 / AUC=0.958（基线） | `backend/models/MODEL_REGISTRY.md` §3 |
| 融合 | 加权融合 + 危机词优先级规则 | 实验（n=1,275） | `backend/app/ml/fusion_engine.py` |
| 风险阈值 | 硬编码各模态分级阈值 | 无临床来源注释 | `backend/app/core/risk_thresholds.py`（`MODALITY_RISK_THRESHOLDS`，mild/moderate/high/critical） |
| 验证设施 | sensitivity/specificity/PPV/NPV/AUROC/Brier + Wilson/Bootstrap CI + 公平性分组 | 代码就绪，性能值"待真实试点" | `backend/app/ml/model_validation.py`、`backend/app/api/v1/model_validation.py` |
| 停用开关 | kill switch（4 个预测端点，Redis + 内存降级） | 代码就绪 | `backend/app/core/kill_switch.py` |

**关键观察**：
- 文本模态 groupwise F1 **0.5864** 才是泛化口径，而 JSON 内 `full_model_eval_on_zh` F1 **0.9972** 是样本内读数，**不可当泛化引用**（`P2_R14_PROJECT_CHARTER.md` §〇.5 已明示）。
- 同一 JSON 存在**阈值口径不一致**：顶层 `"threshold": 0.3`，但其 `groupwise_ooF` 块的 recall=0.5375 / precision=0.645 / F1=0.5864 实际对应 `threshold_sweep_groupwise` 里的 **0.5** 行（0.3 行的 F1 为 0.5719）。→ 阈值来源需在注册前锁定并记录版本（§五 维度 10）。
- `risk_thresholds.py` 的阈值注释只写"v1.16 校准后 / v1.20 重新校准"，**未给临床或统计依据**；同文件 docstring 记录了一个 P0-3 修复：曾因 `NaN >= 阈值` 恒为 False 导致"算不出来"被静默判为"无风险"，现改为显式抛 `NonFiniteRiskScoreError`。这既是工程亮点、也是"安全设计"的良好素材（§五 维度 7）。

**四条关键判定（本报告重点）**：

1. **主体资格是根因性阻断项（不在上表 11 维内）**：医疗器械注册人须为依法登记的境内**企业法人** `[待核验]`。个人、课题组、高校一般不能作为注册申请人。→ 决策者须先回答"是否成立/挂靠企业实体"，否则后 10 维全部无意义。
2. **三档产品定位的监管后果**（见 §一表）：甲档可通过削减功能声明规避器械监管；乙档需完整证据链；丙档本阶段不可行。
3. **性能声明不可合并**：结构化 F1=0.8955（Mendeley PHQ-9）与文本 groupwise F1=0.5864（双语语料）来自**不同数据、不同口径**，不能拼成一个产品级性能指标对外声明。
4. **阈值与门槛无临床依据**：`risk_thresholds.py` 的 mild/moderate/high/critical 与 Brier≤0.20 均为自设；缺决策曲线/净获益与临床共识来源（PMID 41512215 提供"子群净获益"框架）。

## 八、分阶段补齐路线（3 / 6 / 12 个月）

> 纪律：每阶段先定门槛，再出结论；未达门槛不进下一阶段。与仓库既有"门槛先定、结论后出"体例一致。

### 阶段 0（0–3 月）：决策与主体

- **目标**：把"是否做、以什么身份做"拍板。
- **动作**：① 三档产品定位书面决策（甲/乙/丙）；② 主体资格方案（成立/挂靠企业法人）；③ 软件安全性级别判定并留档；④ 建立风险管理（ISO 14971 对应物）与软件生命周期（IEC 62304 对应物）文档骨架；⑤ 对现役模型做 PROBAST 自评 + TRIPOD+AI 差距清单。
- **可交付证据**：路径决策记录、主体方案、软件安全性级别判定、风险管理计划 v0.1。
- **门槛**：三档定位 + 主体方案均落定（否则停止）。
- **明确不做**：不改任何模型与阈值；不宣称性能达标。

### 阶段 1（3–6 月）：证据链
