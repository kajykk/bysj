## 摘要（TL;DR）

心理健康风险系统里，一个"数字很漂亮"的模型指标，可能**根本不成立**——不是模型弱，
而是评估口径本身漏了。本轮把全仓 ML 评估入口做了一次系统审计，得到三件事：

1. **盘清了家底**：AST 扫描 **39 个交付脚本 / 87 个划分入口**，按四类风险（L1 随机
   划分、L2 逐层挑优、L3 阈值在评估集上选、L4 目标泄漏）逐条人工裁定。
2. **量化了"泄漏红利"**：同一批数据换口径，中文语料 **ΔF1 +0.311 / ΔAUC +0.157**；
   并抓到一处最严重的 **L4 目标泄漏**（某"特征"是标签的确定性函数，单特征 AUC=**1.0000**）。
3. **做了补救、并把它变成闸门**：收回 **10 处**被污染的结论、给泄漏脚本加护栏、
   把"目标泄漏检测"升为**提交期闸门**（配真实变异验证）。

随后用**同一套纪律**做了一次全新的方向（纵向早期检测），得到**阴性结论**并如实记账
——证明这套纪律不仅能"证明对"，也能"证伪"，且不自我说服。

**一句话**：本项目的强项不只是"把功能做出来"，更是"**知道自己的数字在什么条件下才算数**"。

---

## 一、为什么这件事值得做

一个心理健康筛查系统的输出会影响真实的人（是否被预警、是否进入人工复核）。因此
"模型指标"不是学术装饰，而是**决策依据**。而评估陷阱的危害恰恰在于**静默**：

- 随机划分把同一被试的增强变体分到训练与评估两侧 ⇒ 模型"背答案"，指标虚高；
- 阈值在测试集上扫描取优 ⇒ 报的是"见过测试集之后"的成绩；
- 特征由标签派生 ⇒ 指标是**同义反复**，换任何交叉验证都修不好。

这些陷阱**不会报错**，只会给出乐观数字。本项目自己就踩过：P2-1 记录的
**groupwise F1 0.5864 vs textwise 0.9964（差 0.41）**，同一批数据、同一模型，
仅划分方式不同。这成为本次审计的第一手动机。

**前沿佐证（三重印证，非自说自话）**：

| 来源 | 结论 |
|---|---|
| 本项目 P2-1 | 随机划分 F1 0.9964 vs 分组 F1 0.5864，差 0.41 |
| `arXiv:2607.02920`（CLeaD） | 说话人身份泄漏把普通话 F1 虚高到 0.954 |
| `arXiv:2610.06465` | small-N 上 best-of-N 逐层挑选把 AUC 虚高 0.09 |

三者同向：**「随机划分 + 逐层挑优」会让评估指标失去意义**。

## 二、方法：可复现、可回归、可变异验证

不是"读代码凭感觉"，而是**工具化 + 可回归 + 配真实变异**：

1. **AST 扫描**（非文本匹配）：遍历 `git ls-files` 跟踪的 `.py`，提取
   `train_test_split / KFold / GroupKFold / StratifiedKFold / StratifiedGroupKFold /
   ShuffleSplit / cross_val_score / cross_validate / …` 的 `ast.Call` 调用点。
   *用 AST 的理由：文本扫描会命中扫描器自己的 docstring，产出假证据。*
2. **四类风险分类法**（见下表），每条候选**人工读码裁定**后才进清单。
3. **口径对照探针** `leakage_delta_probe.py`：同一数据上并行跑"随机 vs 分组"两套
   协议，直接输出 **Δ（泄漏红利）**，并有 `--self-test` 手算自检。
4. **闸门 + 真实变异**：把发现固化为提交期测试，并用**故意注入的变异**证明
   "闸门真的会红、且能还原"。

### 四类评估陷阱（L1–L4）

| 代号 | 问题 | 判据 | 能否靠换 CV 修好 |
|---|---|---|---|
| **L1** | 随机划分不守恒 | 数据有兄弟/重复结构，却用 `train_test_split`/`StratifiedKFold` | ✅ 改 groupwise |
| **L2** | 逐层挑优 / best-of-N 选择偏差 | 同集反复选超参并只报最优 | ⚠️ 需嵌套选择 |
| **L3** | 阈值在评估集上选 | 决策阈值在 test 折上扫描取优 | ✅ 阈值须在训练折内定 |
| **L4** | **目标泄漏** | 特征是标签的确定性/近似确定性函数 | ❌ **换任何 CV 都无效** |

## 三、证据：量化"泄漏红利"

### 3.1 L4 目标泄漏（最严重，最高优先）

`backend/scripts/modeling/v1_24/01_build_mmpsy_features.py`：

```python
def derive_stress(phq9: float) -> float:
    return round(phq9 / 27.0 * 5.0, 4)      # stress_level = phq9 的确定性单调变换
```

而评估标签 `phq9_binary = (phq9_score >= 10)`。**特征与标签一一对应**。实测：

| 量 | 实测值 |
|---|---|
| `corr(stress_level, phq9_score)` | **1.0** |
| 单特征 AUC（`stress_level` → `phq9_binary`） | **1.0000** |
| 标签阈值干净度 | `=1` 最小 10 分；`=0` 最大 9 分 |

**泄漏红利量化**（mmpsy 上重训 LR，5-fold）：12 特征 AUC **0.9997** → 剔除
`stress_level` 后 **0.9212** → 再剔除 `anxiety` 后 **0.6394**。即 0.9997 里
绝大部分是 `stress_level` 一个特征"背答案"背出来的。

**关键澄清（防止误伤）**：训练集本身**干净**——`aligned_features.csv` 的 PHQ-9
子集 `corr(stress_level, phq9_total)=0.5476`（真实字段，非派生）。泄漏**仅限
mmpsy 外部验证**。

### 3.2 L1 兄弟泄漏（中文语料，独立复现）

`chinese_depression_corpus_v1.csv`：8379 行、`source_idx` 仅 1244 个唯一组，
每组最多 7 个增强变体。随机划分会让变体跨 train/eval。实测（生产同款
jieba TF-IDF + LR + 固定阈值 0.3）：

| 口径 | F1 | ROC-AUC |
|---|---|---|
| 随机（文本级） | **0.8860** | **0.9994** |
| 组级（sibling-aware） | 0.5749 | 0.8421 |
| **Δ（泄漏红利）** | **+0.3111** | **+0.1573** |

### 3.3 "有重复数据" ≠ "指标虚高"（对直觉的反例）

mmpsy 结构化特征有 55.9% 重复行、组内标签一致率 100%，按直觉该有巨大泄漏红利；
但实测 **ΔAUC=0.0000、ΔF1=+0.0014**——因为该任务本就近乎完美可分（AUC 0.9996），
是**天花板效应**，不是没泄漏。

> **结论**：一刀切判"随机划分=泄漏"是错的。**必须实测**才知道红利是否存在。

## 四、补救：收回结论 + 护栏 + 升闸门

### 4.1 收回被污染的结论（10 处，历史快照只追加不改）

在 9 个文件中加 `⚠️ 更正（B.5）` 块，**原文一律保留**（可追溯性优先于整洁），
并区分"未更正部分"（仍成立的结论）。其中 2 处是**定义源头**——设计阶段就把
`gap<0` 硬编码解释为"填充噪声"，正是错误结论的成因。

**决策影响记账**：逐条核对 go/no-go 依据后确认——**未发现任何决策因污染结论被推翻**。
被污染的恰是两个"支持继续"的乐观读数（0.9993）与一个解释性结论，均未改变决策方向。
本轮**只记账上报，不自行翻案**。

### 4.2 代码护栏（防复发，但不篡改历史）

对泄漏脚本 `01_build_mmpsy_features.py`：加 ⛔ 横幅、`LABEL_DERIVED_FEATURES`
登记表、默认路径置 `unavailable`、仅 `--allow-historical-repro` 才复现历史派生——
**无真实 stress 字段时应标"不可得"，而不是用标签伪造一个**。

### 4.3 升为提交期闸门（这是"防复发"的关键）

把 L4 检测从"一次性审计"变成**提交期测试**：每个从标签源派生的特征都必须在
登记表声明（AST 差集为空）、默认路径不得产出标签同源特征（**AST 分支断言**）。
配真实变异验证（M6/M7/M8，红→还原绿）。

### 4.4 了结未验证项

- 5 处阈值/权重挑优逐条读码裁定（含追源头：某脚本阈值实为在 **val** 折选，**不成立 L3**）；
- `aligned_features.csv` 56 组/112 行重复（0.392%）：ΔAUC **+0.0043** ⇒ **可忽略**（定量结论，不留预估）。

## 五、横向验证：用同一套纪律做一次新方向

为避免"自说自话"，用同一纪律做了一次全新方向——**纵向早期检测**（对齐 eRisk
Task 2，`arXiv:2609.08161` 学习式停止策略）。

- **数据 gate（先实测）**：语料每用户一行、无时间列；生产库无多时点记录；
  `init_db` 不灌观测数据 ⇒ **无真实纵向数据**，转而使用**显式标注 `synthetic`
  的可复现仿真基准**。
- **指标口径写死**：`ERDE@k`（未报警恒罚 1、提前报警得负=奖励）+ `F_latency`，
  **禁用普通 F1**（那是时点口径）。
- **结果（5-fold，按用户分组）**：

| 档 | ERDE50 ↓ | F_latency ↑ |
|---|---|---|
| a 时点 + 固定阈值 | **0.0052** | 0.6721 |
| b 分层阈值 | **−0.0455** | **0.7049** |
| c 学习式停止（MLP） | 0.1958 | 0.5820 |

- **判定**：c 相对 a 两向均不达标 ⇒ **阴性结论**，不进主路径。
- **诚实记账**：归因（c 过激：提前量换来漏报翻倍与误报上升）；并**明确标注基准
  过易**（a 档近天花板）⇒ **结论不可外推**；**不做参数自救**（调到达标=在评估集调参，
  正是 L3 教训）。

> 这一步的意义：这套纪律不仅能确认"对"，还能**干净地证伪并记录"为什么**"。

## 六、沉淀的工程纪律（可复用）

本过程反复撞上同一类坑，逐次固化为规则：

| 纪律 | 触发实例 |
|---|---|
| **断言钉交付形态，不钉本机状态** | 扫描器用 `rglob` 扫本机工作树（42）而 CI 只有 39；改用 `git ls-files` + AST 不变量 |
| **断言钉结构，不钉字面量** | 闸门用文本断言 `'x' in src`，字符串还在源码里就绿 ⇒ 分支被改成 `if True` 也骗过；改 AST 分支断言 |
| **判据必须实测，不信转引** | 路径常量 `parents[2]` 指向错层，漏扫 4 倍文件；修正前后 28→118 入口 |
| **改口径才谈整改，先检测后补救** | 检测轮只记账不改数；补救轮也只"收回结论/加护栏"，不篡改历史读数 |
| **阴性即阴性，不自我说服加码** | 方向 C 阴性，明确不做参数自救 |
| **历史快照只追加不改** | 更正一律加块，原文保留，区分"未更正部分" |

## 八、结论

在一个"AI + 全栈 + 可观测性"的工程项目里，**功能正确**与**评估可信**是两件事，
且后者更容易被忽视。本报告记录了一次系统性的评估可信度治理：

- **可复现**：扫描器、探针、生成器、闸门全部入库，配固定种子与自检；
- **可回归**：发现固化为提交期测试，配真实变异证明有效；
- **诚实**：阳性发现如实量化，阴性结论如实立项，未验证项如实挂账。

这既是本项目"**知道自己的数字在什么条件下才算数**"的证据，也是一套可移植到
任何 ML 项目的评估纪律。
