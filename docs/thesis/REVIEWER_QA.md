## Q1. 域内 ROC AUC 高达 0.9884 [C-05]，为什么论文不主张泛化？

因为 AUC 只度量**同一测试分布内部**的排序能力，而泛化是跨分布问题，两者不是同一件事。
本文的泛化证据全部来自跨数据集实验，结论为负：生理 × Kaggle Wearable 的 ROC AUC
仅 0.5120 [C-12]，其 95% CI [0.5006, 0.5233] 覆盖 0.5，与随机不可区分；文本模态
唯一可引用的泛化口径是 groupwise 划分下的 F1 = 0.5864 [C-22]，远低于同分布读数。
域内 AUC 高而 Recall 仅 0.6000 [C-03] 同时说明：瓶颈在阈值位置与样本量，不在排序结构
（诊断实验见 Q2）。在只有负迁移证据的情况下主张泛化，属于没有证据支撑的外推。

## Q2. Recall 0.60 在抑郁筛查场景下「行不行」？作为系统你们怎么敢交付？

不行——论文明确这样写，并给出机制解释。域内混淆矩阵 TP=33 / FP=0 / FN=22 / TN=102
[C-06]：漏报 22/55 例阳性，Recall 0.6000 [C-03]，CI 宽至 [0.4717, 0.7292]。
已定位主因是生产链路的标准化参数与模型权重不配套（P0 缺陷，未修复）：仅把 scaler
换成在当前训练集上重拟合的参数，Recall 即达 0.9455 [C-08]、F1 0.9369 [C-07]，
而 ROC AUC 几乎不变（0.9884 [C-05] vs 0.9841 [C-09]）——问题在标准化参数，
不在排序能力。注意 0.9369 / 0.9455 是诊断读数，**不得**宣称为模型性能（台账备注）。
本文不交付「筛查就绪」结论：缺陷整改与更大样本外部验证是后续工作前提。

## Q3. n = 157 的样本量，结论可靠吗？

分两类结论看。**负向结论可靠**：生理跨设备迁移失败在 n = 10000 [S-02] 上复现
（AUC 0.5120 [C-12]，CI 覆盖 0.5），大样本让「与随机不可区分」成为硬结论。
**域内正向结论只是中等强度**：n = 157 中阳性仅 55 例，Recall 的 CI 宽约 0.26
[C-03]，Accuracy 0.8599 [C-01] 的 CI 也宽约 0.11；因此本文所有指标一律附
bootstrap 95% CI（B = 10000，seed = 42），不报裸点估计。文本侧另有一个
n = 8379 [S-05] 的 groupwise 交叉验证（F1 0.5864 [C-22]）作为不同样本量下的
交叉参考，但其语料与生理模态不可比。

## Q4. 旧文档里 0.85 ~ 0.97 那一组生理指标（例如 F1 约 0.85、AUC 约 0.97）为什么不出现在论文里？

**不引用。** 那一组（样本量 n = 139）已列入黑名单 B-01：仓内 `stratified_split`
（random_state = 42）恒给出 719 / 153 / 157 而非记录的 719 / 171 / 139（不可复现，
黑名单）；artifact
的 scaler 统计量与仓内三份生理数据全不匹配（如 sleep_quality 均值 5.43 超出 1–5
量表）；训练脚本从未入库——三重证据表明其**不可复现**。同类还有：registry
`test_f1` 0.9530 [B-02] 是第三套数字（禁用：hidden_dims 与实际权重不符，manifest 已自认
过期）；0.8527 [B-03] 是 bootstrap 均值被误记入 point 位（禁用）。正确替代是台账
C-01 ~ C-06（n = 157 新口径）。论文只承认可由已提交产物复算的数字。

## Q5. 文本模态 F1 0.9862 [C-19] 是不是刷分？

是，论文按泄漏证据处理，并强制与真泛化口径同引。该 OOD(strict) 子集的构造本身
来自泄漏审计：1275 条 original 全在训练语料、1175 条 mmpsy_augmented 全在训练
增强集中；同一模型随机划分下的读数 0.9964（台账 C-22 备注）与 0.9862 同属
同源近重复导致的虚高。文本模态唯一可引用的泛化读数是按 user_id 分组、组间不重叠的
groupwise 交叉验证 F1 = 0.5864 [C-22]。两者相差约 0.40，即「同源泄漏」与
「真泛化」的差距；单独引用 0.9862 [C-19] 而隐去 0.5864 [C-22] 在本文纪律下不允许。

## Q6. 为什么全文没有任何一个正向的跨数据集迁移结果？

因为实测没有。两个可运行单元全部为负或不可用：生理 → Kaggle Wearable 迁移失败
（Accuracy 0.4801 [C-10]、F1 0.3639 [C-11]、AUC 0.5120 [C-12]，CI 覆盖 0.5），
且该数据集「未确证未参与训练」（其评估 json 的 dataset.note 原文如此）；文本 →
OOD 的高指标是泄漏证据（Q5）。其余迁移矩阵格子为 N/A：缺数据或缺配对产物。
生理信号强设备相关（采集设备、佩戴方式、采样率差异），线性文本模型对同源近重复
过敏感——两者都没有给出正向外推的证据，论文如实写 0 个真外迁单元。

## Q7. 外部审稿人如何复算论文里的每个数字？

一条命令（只读，不写文件）：

```bash
cd backend
.venv/Scripts/python.exe scripts/modeling/eval/verify_thesis_numbers.py
```

它从**已提交**的逐样本 csv / 评估 json 复算台账全部 35 条登记（点估计用独立实现，
CI 用与评估脚本同一抽样序列），并比对论文章节表格、扫描黑名单、检查引用纪律。
复算分层如实说明：需要原始数据集的 `01/02` 评估脚本只能在有数据的机器上以
`--report-only` 运行；CI 干净 checkout 的复算层就是上述 csv/json 层。
「提交产物 == 单命令产物」的硬闸门在 ROUND_27，本轮未重跑（记账，见台账 §〇）。

## Q8. 融合权重敏感性结论能外推到生产配置吗？

只能定性外推。扫描覆盖生产权重 0.55/0.3/0.15 [X-06]：仅当模态结论冲突时风险等级
对权重敏感，且翻转点恰在生产权重处（2→1 @0.55 [X-04]、2→3 @0.55 [X-05]）；
三组一致场景（agree_low / agree_high / mid_all）在全部 9 行权重下等级不变
[X-01 ~ X-03]。但输入是 5 组**手写**场景，其历史「全 1.0000」行已叙事禁用
[B-04]——该扫描说明融合层定性行为，不构成性能证据，不能据此声称生产定级稳健。
