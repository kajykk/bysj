## 一、A 摊：G1 收口

### 1.1 缺口实测（先复现，再动手）

| 指标 | 提交版 json（`tei` 顺序 + 全精度） | `--report-only`（csv 升序 + 6 位） | 差 |
|---|---|---|---|
| Recall CI | [0.468733, 0.728814] | [0.471698, 0.729167] | +3.0e-3 / +3.5e-4 |
| F1 CI | [0.638282, 0.843137] | [0.641026, 0.843373] | +2.7e-3 / +2.4e-4 |
| AUC CI | [0.969435, 0.999020] | [0.969948, 0.998976] | +5.1e-4 / −4.4e-5 |
| Acc CI / point / 混淆矩阵 | — | 完全相同 | 0 |

与提示词给的偏差量级一致，但**归因不同**（见 1.2）。

### 1.2 归因：**行序**是根因，精度只在阈值层面可区分

`write_predictions_csv` 按 `row_index` 升序落盘，而指标/CI 用 `tei`（split 后 shuffle）顺序计算；
`--report-only` 从 csv 按升序读回 ⇒ bootstrap 的 `rng.randint` 位置索引落到**不同的 (y, score) 对**
⇒ CI 端点系统性偏移。

变异证据（`mutate_p2_54_round27_precision.py`，5/5 PASS）：

| 组 | 操作 | 结果 |
|---|---|---|
| M1 | 最接近阈值的样本 ±1 ulp | 指标全不变（如实记录：1 ulp 不可区分） |
| M2 | 该样本设为 `0.49999999999999994`（全精度 csv） | TP/FP/FN/TN 33/0/22/102 → **32/0/23/102**；F1 0.75 → **0.735632** |
| M3 | **对照臂**：6 位 csv 上同样操作 | 写入后被舍入成 `0.500000` ⇒ 仍判正 ⇒ **指标不变** ⇒ M2 证明精度确实进入计算 |
| M4 | 6 位 csv 全量复算 | CI **完全不变** ⇒ 本数据下 6 位舍入未改变任何排序位置 |
| M5 | 全精度 + **`tei` 顺序重排** | F1 CI 复现 ROUND_26 旧值 **[0.638282, 0.843137]** ⇒ **顺序是根因** |

### 1.3 修复

1. `:.6f` → **`.17g`**（float64 往返无损）；
2. 指标/CI 改用**落盘行序**（`y_eval/s_eval/refit_eval` 从 `rows` 取）；
3. `--report-only` **同写 JSON + MD**（此前只写 MD，JSON 会静默陈旧）；
4. 抽 `dataset_block/build_payload/write_json` 两模式共用（字段/舍入完全一致）；
5. `.gitattributes` 给评估产物加 `eol=lf`（否则 Windows checkout 转 CRLF ⇒ sha 与 `.sha256` 失配）。

### 2.4 两个降级单元的读数

**P × Kaggle Wearable（n=10,000）** —— 跨数据集压力测试、下界：

| 指标 | 点估计 | 95% CI |

v2 训练脚本未入库，**无法确证 Kaggle 未参与训练**。

**T × OOD(eda strict)（n=2,523）** —— 域内压力测试：

| 指标 | 点估计 | 95% CI |
|---|---|---|
| Accuracy | 0.9945 | [0.9913, 0.9972] |

真 groupwise 泛化口径是 F1 0.5864。

### 2.5 工程记账：n=10^4 的 bootstrap 加速（与 01 逐位对拍）

01 的 `auc_score` 是纯 Python tie 循环；n=10,000 × B=10,000 时 >5 分钟（实测被系统终止）。
02 改用 `scipy.rankdata` 的向量化平均秩，并**保持 `rng.randint` 调用序列与 01 完全一致**
（先用多项分布近似试过：与 01 差 3.9e-4，不可接受 ⇒ 放弃）。

`--verify-fast` 在 text_ood 上与 01 对拍：**max CI diff = 0.000e+00（PASS）**，
逐指标（acc/prec/rec/f1/roc_auc）全部逐位相同。physio_kaggle 全量跑完 17 秒。

## 四、未验证记账

- **「真外迁 = 0」是实测结论，不是本轮的能力上限**：仓内确实没有与训练集不同源、且
  特征/标签齐备的数据。硬凑映射（如把 `Mood_Rating` 当 `sleep_quality`）能造出数字，
  但那不构成证据 —— 本矩阵拒绝这样做。
- `physio_kaggle` 的「未参与训练」无法确证（v2 训练脚本未入库，ROUND_26 已证 artifact 与
  仓内三份数据都不匹配）⇒ 该单元只作压力测试，不作外迁结论。
- 两个降级单元的 CI 用 02 的 `fast_bootstrap`（同 RNG 序列、向量化 AUC）；已与 01 逐位对拍，
  但**该对拍只在 n=2,523 的 text_ood 上做过**，n=10,000 的 physio_kaggle 无 01 对照
  （01 在该规模下不可完成）。
- 未在第二台机器/不同 numpy 版本上重跑（env 指纹已落盘）。
- OOD 的泄漏标注沿用 `v1_27/02` 的口径（v1 分组、v2_clean original、reddit 全量）；
  本轮复算的 1275/1175/2523 与既有 `ood_validation_results.json` 一致，但未重新审计该口径本身。
